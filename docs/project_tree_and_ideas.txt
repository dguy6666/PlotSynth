Empty state / First card conflict
Having both ProjectCard and AddNewProjectCard listed directly inside GridView.builder is conceptually fine, but remember that in the code's itemBuilder, you will use an if (index == 0) check to return AddNewProjectCard, and return ProjectCard for index - 1.

Build ONE ProjectWorkspacePage with 5 tab views.

Never push 5 separate route pages for different areas of the same project. Here is why:

    Shared Project Context: All 5 tabs (e.g., Notes/Editor, Character Index, Timeline/Events, Inconsistency Audit, Settings/Export) belong to the same project entity. Having one parent screen allows you to load the project's data once at the root and provide it downward without re-fetching or passing arguments on every screen switch.

    Preserving Tab State: If you use a single page with TabBarView and wrap your tab bodies in AutomaticKeepAliveClientMixin, switching between tabs won't lose your scroll position, cursor location in an open note, or filter state in the audit report.

    Navigation Simplicity: When the user taps the back button (Navigator.pop(context)), they expect to return to the MainScreen (Projects Grid), not to navigate backward through 12 internal tab switches.
